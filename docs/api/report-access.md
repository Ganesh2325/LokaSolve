# Report access and media

This describes the current process. ADR 0002 is unchanged.

## Who can read a report

The decision is made in the database policies and again in the service query. The browser cannot widen it.

| Caller | Result |
| --- | --- |
| The person who filed the report | Stored report, including the address and coordinates they supplied |
| Super administrator (`admin:roles_grant`) | Stored report |
| Responder with an assignment that is not `rejected` | Case fields needed for the work: narrative, place, coordinates, and status |
| Active member of a municipality, utility, or institution | Case fields only when the report's locality text exactly matches one jurisdiction recorded for that organization |
| Any other signed-in person, and the report is public | Public card only |
| Any other signed-in person, and the report is private | `404` `not_found` with `That report is not available.` |
| Missing id | The same `404` and the same message |

A public card contains `id`, `category_label`, `locality_text`, `status`, `created_at`, `visibility` = `public`, and `summary`. It does not contain `description`, `address_text`, `latitude`, `longitude`, `answers`, or `identity_visible_to_resolver`.

`GET /api/v1/nearby` returns the same kind of card. It does not return the narrative, an exact address, coordinates, or media.

Support agents keep their user, organization, and audit permissions. Those permissions do not include every private report. Counts for the operations screen come from `issue_metrics()`, which returns numbers and not report rows.

## Who can change a report status

The person who filed the report, and a super administrator, can set the category label. Another person who cannot see the report receives `404`. A person who can see it but cannot change it receives `403`. Assignment progress follows the assignment state machine: a responder cannot confirm the resident's outcome.

Rejecting an assignment removes that responder's access to the report and its media.

## Media

`POST /api/v1/issues/{issueID}/media` accepts one multipart field named `file`. Only the report owner can upload.

The server reads the bytes and allows:

| Bytes | Extension | Stored type | Maximum |
| --- | --- | --- | --- |
| JPEG | `.jpg`, `.jpeg` | `image/jpeg` | 4 MB |
| PNG | `.png` | `image/png` | 4 MB |
| WEBP | `.webp` | `image/webp` | 4 MB |
| GIF | `.gif` | `image/gif` | 4 MB |
| MP3 | `.mp3` | `audio/mpeg` | 4 MB |
| M4A | `.m4a` | `audio/mp4` | 4 MB |
| MP4 | `.mp4` | `video/mp4` | 4 MB |
| WEBM audio | `.weba` | `audio/webm` | 4 MB |
| WEBM video | `.webm` | `video/webm` | 4 MB |

A declared `Content-Type` that disagrees with the bytes is rejected. An extension that disagrees with the bytes is rejected. Empty files, truncated files, archives, and executables are rejected. The stored id and file name are generated by the server. The response does not include a database path.

Download requires the owner, an active assignee, an in-jurisdiction officer, or a super administrator. A missing file and a forbidden file both return `404` `That file is not available.` The response sets `X-Content-Type-Options: nosniff`, `Content-Disposition` with the server file name, `Cache-Control: private, no-store`, and `X-Malware-Scan`.

`malware_scan` and `X-Malware-Scan` are `not_scanned` while no scanner is configured. That means a scanner did not run. It does not mean the file is clean. `internal/workflow/scan.go` defines `MalwareScanner` for a later scanner. No scanner is connected in this process.

Public report visibility does not grant media list or download access.
